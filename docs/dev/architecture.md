# システムアーキテクチャ

ステータス: **方針ドラフト**  
セットアップ詳細は実装開始後に `docs/dev/setup.md` を追加する。

## 1. 全体像

```text
┌─────────────────┐     ┌──────────────────────────────┐
│  Mobile App     │     │  Admin Web（運用者）            │
│  録音・確認・編集 │     │  ユーザー／ストレージ／課金補助  │
└────────┬────────┘     └──────────────┬───────────────┘
         │ HTTPS API                    │ HTTPS
         ▼                              ▼
┌─────────────────────────────────────────────────────┐
│                 API Server                           │
│  認証・ユーザー・話者・セッション・課金・同意           │
│  ジョブ投入（文字起こし／自叙伝／プロファイル）         │
└───────────────┬───────────────────┬─────────────────┘
                │                   │
                ▼                   ▼
        ┌──────────────┐    ┌──────────────────┐
        │ Object Store │    │  Worker / Queue   │
        │ 音声・成果物  │    │ ASR / LLM / 集約  │
        └──────────────┘    └────────┬─────────┘
                                     │
                                     ▼
                              ┌─────────────┐
                              │  Database   │
                              │ メタデータ   │
                              └─────────────┘
```

## 2. 論理コンポーネント

| コンポーネント | 責務 |
| --- | --- |
| Mobile App | 録音、オフライン一時保存、アップロード、文字起こし確認、タグ編集、自叙伝閲覧／編集 |
| API Server | 認証、CRUD、権限（entitlements）、署名付きアップロード URL、ジョブ API |
| Worker | 文字起こし、感情／イベント抽出、自叙伝生成、ライフプロファイル生成 |
| Object Storage | 音声ファイル、中間成果、PDF などのバイナリ |
| Database | ユーザー、話者、セッション、テキスト、同意、プラン |
| Admin | 運用者向け監視・手動プラン変更・削除依頼対応 |
| 外部 AI | ASR（音声認識）、LLM（要約・自叙伝・対話）。ベンダーは後で確定 |

## 3. 想定リポジトリ構成（モノレポ案）

tanagrid と同様、用途ごとにアプリを分ける。

```text
kataritsugi/   # または lifehistory/
├─ apps/
│  ├─ server/          # API + Admin
│  ├─ mobile/          # React Native / Expo 等（後で確定）
│  └─ worker/          # 非同期ジョブ（server 内でも可）
├─ packages/
│  ├─ shared-types/    # API DTO・プラン型
│  └─ client-sdk/      # モバイル向け API クライアント
├─ docs/               # 本ドキュメント
└─ compose.yml         # 開発用 DB / キュー
```

技術スタックは実装フェーズで確定する。方針だけ先に固定する:

- モバイルとサーバは **JSON API + Bearer トークン**
- 音声バイナリは API 本体を経由しすぎない（**直接アップロード to Object Storage** を推奨）
- OS 依存の録音はモバイル側に閉じ込める
- 共有型は `packages/shared-types` に寄せる

## 4. 通信方針

```text
Mobile ──(1)──▶ API : セッション作成・アップロード許可取得
Mobile ──(2)──▶ Object Storage : 音声 PUT（署名 URL）
Mobile ──(3)──▶ API : アップロード完了通知 → ジョブ投入
Worker ──(4)──▶ Object Storage : 音声取得
Worker ──(5)──▶ ASR / LLM
Worker ──(6)──▶ DB : 文字起こし・生成結果を保存
Mobile ──(7)──▶ API : ポーリング or プッシュで結果取得
```

- 認証: `Authorization: Bearer <token>`
- プラン権限: `/me` 相当で entitlements を返す
- 大きな生成は非同期。クライアントは job status を購読

## 5. セキュリティとプライバシー

| 項目 | 方針 |
| --- | --- |
| 保存時暗号 | Object Storage のサーバサイド暗号＋DB の秘匿カラム検討 |
| 転送 | TLS 必須 |
| アクセス制御 | 契約アカウント単位。家族は招待ロール |
| 音声の取り扱い | ログに音声・全文を出さない。ジョブ ID のみ |
| 外部 AI | 学習利用の可否を契約で確認。可能ならゼロリテンション |
| 削除 | ユーザー削除依頼で DB + オブジェクトを消去（バックアップ残存期間を文書化） |

## 6. スケーリングの考え方

- 初期: API と Worker を同一クラスタ、キューは Redis / DB バックエンドいずれか
- 録音増: Worker を水平スケール、ASR をバッチ／ストリーミングで選択
- プレミアム優先: キューに priority を持たせる
