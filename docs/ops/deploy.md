# 本番デプロイ方針（概要）

ステータス: **方針ドラフト**  
具体的な手順・環境変数一覧はインフラ確定後に追記する。

## 1. 構成方針

| 要素 | 方針 |
| --- | --- |
| API / Admin | Linux 上のコンテナまたは従来型アプリサーバ |
| Worker | API と同クラスタで水平スケール可能に分離 |
| DB | マネージド RDB（PostgreSQL 想定） |
| Object Storage | S3 互換 |
| キュー | Redis 等 |
| モバイル配信 | App Store / Google Play |

開発初期は Docker Compose で DB・ストレージ互換・キューを再現する。

## 2. 環境

| 環境 | 用途 |
| --- | --- |
| local | 開発者マシン |
| staging | ストア提出前検証、ASR/LLM 接続試験 |
| production | 本番 |

staging と production で AI ベンダーのキー・データ保持ポリシーを分ける。

## 3. デプロイの基本流れ（案）

1. マイグレーション
2. API / Worker のローリング更新
3. ヘルスチェック（`/up` 相当）
4. モバイルはストア審査があるため API 後方互換を維持

## 4. 監視したいもの

- 5xx 率、ジョブ失敗率、文字起こしレイテンシ
- ストレージ使用量（アカウント別）
- キュー滞留（premium 優先が効いているか）
- 同意・削除リクエストの未処理件数

## 5. バックアップと削除

- DB: 日次バックアップ
- オブジェクト: バージョニングは個人データ保護方針と両立するよう設計
- ユーザー削除: 猶予期間と物理削除の完了条件を runbook 化
